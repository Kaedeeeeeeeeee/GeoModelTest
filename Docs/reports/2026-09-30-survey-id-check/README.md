# 问卷中再次输入回答者ID + 学生同意窗口标题 — 2026-09-30

版本 `2026.09.30-survey-id-check`，itch.io 构建 **`2039338`**，数据库迁移 `20260930043339_survey_respondent_id_check`。

## 背景

回答者ID在开头的家长同意页输入，New Game 时绑定到游玩记录，问卷回答会自动对应到这个ID。老师希望在问卷里再输入一次，作为 double check。

## 问卷中的ID确认

- **位置**：问卷最后、「回答を送信する」按钮正上方。放在顶部时，出错提示在页面最底部，手机上看不到，所以移到这里。
- **显示条件**：打开问卷时服务器返回 `respondentIdRequired`。只有存在家长同意记录（`guardian_consents`）的参加者才会显示。其他研究方式的问卷不变。
- **文字**：
  - 标题：「あなたの回答者ID」
  - 说明：「ゲームのはじめに保護者の方が入力した回答者IDを、確認のため、もう一度入力してください。」
  - 占位符：「例：p1234567」
- **规范化**：与家长页相同。全角、大写、空格、破折号自动整理，缺少的「p」自动补上，离开输入框时显示整理后的结果。
- **未输入或格式不对**：不发送，显示「回答者IDを入力してください。」或「回答者IDは「p」と数字7桁で入力してください（例：p1234567）。」。
- **与家长页不一致**（用户选择「提醒后仍可提交」）：服务器返回 409 `respondent_mismatch`，页面显示「はじめに保護者の方が入力した回答者IDと一致しません。もう一度確かめてください。まちがいがなければ、そのまま「回答を送信する」を押してください。」。用同一个ID再按一次就会提交，改了ID则需要重新确认。
- **草稿**：输入的ID和回答一起保存在 `sessionStorage`，重新加载后恢复。
- **老师预览页**（`preview.html`）：同样显示输入框，只检查格式，不比对。

## 服务器

- `survey_responses` 新增两列：
  - `respondent_id`：问卷中输入的ID。
  - `respondent_id_matches`：提交时是否与家长页一致，`false` 表示学生确认后提交了不同的ID。
- ID 存在回答 JSON 之外。没有家长同意记录的参加者，这两列为 null。
- `use_survey_ticket` 改为 4 个参数（`p_respondent_id`、`p_confirm_respondent_mismatch`），旧的 2 参数版本已删除，仅 `service_role` 可执行。
- 不一致时返回错误码 `GQ409`，`game-survey` 转换为 HTTP 409。
- `game-survey`：submit 只多接受 `respondentId`（字符串，最多 20 个字符）和 `confirmRespondentId`（布尔值）。

## 导出

- `survey-export.sql` 和 `research-admin.py export` 新增 `survey_respondent_id`、`respondent_id_matches` 两列。
- `research-admin.py completers`：交给テスティー的文件仍然是家长页的ID，每个不一致的人会另外打印一行，由研究者人工判断。

## 学生同意窗口标题

`ui.consent.title` 改为「理科 3D ゲーム型教材に関する研究に参加する生徒の皆さんへ」（三种语言相同）。

- 老师原文是「研究を参加する」，按用户确认改为「研究に参加する」。
- 老师的 `教材利用本人同意.docx` 中标题仍是「研究への参加について」。文件要求游戏内文字与文件一致，需要请老师同步修改文件。
