## 1. 首次操作引导

研究室开场对白和第一道题结束后、玩家首次自由移动前，显示一屏日文操作说明。电脑介绍 WASD、鼠标、E / F 和 Tab；手机和平板介绍摇杆、滑动视角、互动和道具按钮。

引导显示时暂停角色与游戏；确认后恢复操作。继续存档不会重复显示，开始新游戏会重新显示。

![手机和平板操作说明](mobile-guide.png)

## 2. 关闭本次研究不使用的仓库入口

保留研究室中的柜子外观及已有存储数据，关闭仓库提示、触发器、键盘 / 触控入口，以及旧 UI 的直接打开路径。正常调查和道具系统继续使用。另修复了旧仓库关闭按钮及 Escape 的输入恢复逻辑，便于未来重新开放时正常退出。

![关闭仓库入口后的研究室](warehouse-disabled.png)

## 3. 实际验证中发现的手机输入问题

角色可以先于手机输入管理器创建，导致角色没有取得输入引用。浏览器中出现摇杆能拖动而角色不移动的现象；调用现有初始化方法重新连接后，触控移动恢复。现已在首次输入时自动连接稍后创建的管理器，无需玩家操作。

新增回归测试创建角色后再创建手机输入管理器，经过引导的暂停与恢复，验证摇杆输入确实改变角色位置。

## 验证记录

- PlayMode：15 / 15 通过，覆盖操作引导、手机输入延迟创建、仓库禁用与退出、嵌套菜单、无人机和钻车输入。见 [测试结果](playmode.xml) 和 [简表](test-summary.json)。
- 最终 WebGL 构建成功，构建错误数 0；核心资源约 123.57 MB。
- 实际 WebGL：电脑与触控说明均在开场结束时自动出现；按钮可关闭；继续存档不重复显示。电脑按键可移动，F 不打开仓库。
- 截图来自 Ego Lite 中实际运行的 Unity WebGL 画布。常规浏览器截图接口超时，因此从同一页面的实际绘制帧导出 PNG。
- 手机验证使用 844 × 390 横屏、手机 User-Agent 和触摸事件模拟，不等同于物理 iPhone / Android 验收。Ego Lite 出现过指针锁定错误，本次不宣称完成桌面鼠标锁定的跨浏览器验收。
- 测试使用独立 localhost 来源，不输入研究邀请码。Unity 本机偏好和持久化文件在测试 / 构建后恢复。

最终构建重新加载并继续游戏后，未调用诊断方法，仅通过触摸事件拖动摇杆，角色正常移动。
