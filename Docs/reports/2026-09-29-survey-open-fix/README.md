# 问卷打不开（iPhone）修复 — 2026-09-29

版本 `2026.09.29-survey-open-fix`，itch.io 构建 **`2035650`**。

## 现象

2026-09-29 20:17，在 iPhone（Safari）上测试（回答者 ID `p1231231`，构建 `2026.09.29-consent-form-fix`）。游戏结算画面点「アンケートに答える」后，显示「接続を確認して、もう一度ボタンを押してください。」，再按也一样，问卷始终打不开。

## 服务器记录

同一网络（IP 相同）下，iPad 的两次测试都能打开问卷。

| 时间 | 请求 |
| --- | --- |
| 20:14:18 | 匿名登录 → `research-participation`（开始参加） |
| 20:14–20:17 | `game-ingest-v2` 定期上传，全部 200 |
| 20:17:09 | 最后一次上传（`FlushForSurvey`） |
| 20:17:10 | `game-survey` issue → 200，`survey_tickets` 有记录 |
| 20:17:10–11 | 结束场次（`end_reason = post_game_survey`） |
| 20:17:11 之后 | 这台 iPhone 再没有任何请求，问卷页面的 `open` 没有到达服务器 |

操作记录 158 条、答题 16 条都已在服务器上。

## 原因

`SurveyGateway.OpenRoutine` 在拿到问卷票据、结束场次之后，还会调用 `WebGLFileSync.FlushAndWait`，把游戏进度写进浏览器 IndexedDB，最多等 8 秒。写入失败或超时就显示 `survey.retry`（「接続を確認して…」），不打开问卷。这是结束场次之后唯一还会显示这条提示的步骤（`SurveySettings` 缺失在正式构建中不会发生）。

重试时票据已经存在本地，不会再发请求，直接回到同一个写入步骤，所以一直失败。这和服务器上 20:17:11 之后没有任何请求一致。

iPhone Safari 的 IndexedDB 为什么失败，没有设备端日志，无法确认。可能与内存紧张有关。

## 修改

`Assets/Scripts/Backend/SurveyGateway.cs`：本地写入失败时只记警告，照常打开问卷。

- 研究数据（操作记录、答题）在此之前已经上传。上传失败时仍然显示 `survey.retry`，这时的提示是准确的。
- 问卷回答由问卷页面直接提交到服务器，与本地进度无关。
- 唯一影响：本地进度没存上时，之后在同一台设备上重新打开游戏，可能从较早的存档开始。
