## 项目现状与共同依赖

- 构建场景顺序为 StartScene → MainScene → Laboratory Scene。标题菜单由运行时脚本创建；设置、任务、剧情等也大量使用运行时 UI。
- 主要入口分别为 StartMenuBootstrap、SettingsManager、InventoryUISystem、QuestManager、StoryDirector；应沿用现有系统进行修改。
- 多个系统分别修改光标、玩家控制和 Time.timeScale。BUG-002 的修复应建立共用的界面输入规则，供返回标题、剧情日志和结算界面使用。
- 当前教学路径在钻塔采样后播放 beat3 → beat4 → 报告；代码仍保留较长的旧章节链。BUG-007 必须明确教学路径，避免接回旧章节 5、6。
- 当前评分器有 11 个固定问题 ID；“任务 1/10”应是教学步骤的显示方案，不能直接把题数改为 10。
- 本地存档分散在剧情 flags、任务完成状态、工具解锁、背包、仓库和答题记录中；位置等部分场景状态目前只在内存维护。返回标题与刷新恢复需要明确统一的存档检查点。
- 研究功能已实现匿名认证加参与码验证。正式研究入口在当前配置中关闭，开发入口开启；这一轮先在开发测试环境验证现有流程。

## BUG-001：标题画面、日语与退出

**现状与证据**

[StartMenuBootstrap.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/SceneSystem/StartMenuBootstrap.cs:61) 创建半透明背景和简单按钮，主要按钮直接使用英文字符串。有存档时已经显示 Continue / New Game，无存档时显示 Game Start。

还存在一个需要优先处理的生命周期缺口：菜单宿主被 DontDestroyOnLoad 保留，但 StartMenuCanvas 是独立的场景对象；BuildUI 只在 Awake 调用，没有在重新进入 StartScene 时重建。按这条代码路径，首次离开标题后再返回可能没有菜单。

OnQuitGame 仅调用 Application.Quit。Unity Web 平台的 Quit 不负责网页导航；浏览器也不保证脚本能关闭用户打开的标签页。因此退出的可靠目标应是回到 itch.io 游戏页，并提供可点击的页面链接作为嵌入限制下的兜底。[Unity 文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Application.Quit.html)、[浏览器关闭窗口限制](https://developer.mozilla.org/en-US/docs/Web/API/Window/close)。

**修改计划**

1. 补齐进入/离开 StartScene 的菜单创建、销毁和事件解绑，确保每次进入都只有一个有效菜单和 EventSystem。
2. 统一显示“新游戏”“继续游戏”“设置”；无存档时禁用或隐藏继续按钮。有存档的判断应检查可恢复的进度内容，避免仅因存在空键而显示继续。
3. 使用现有本地化服务与语言变化事件更新标题、按钮和弹窗；把布局制作成可复用的 UI prefab，减少后续视觉调整对流程代码的影响。
4. 视觉建议：以野外地层和研究室为主题背景，保留 Geo Model 名称，增加简短的调查主题说明；按钮尺寸、间距与焦点状态保持一致。先复用项目场景和已有角色素材，再补正式主视觉。
5. WebGL 增加网页退出桥接和可配置的 itch.io 返回地址；测试全屏、嵌入页、独立页面的实际行为。保存完成后再导航，导航受限时显示用户可点击的返回链接。

**验收**：首次启动、已有存档、反复返回标题均可操作；切换三种语言立即刷新；网页退出有明确可见的结果；继续游戏可恢复正确教学阶段。

**优先级/依赖**：菜单重建与退出为高优先级，与 BUG-009 共用返回流程；主视觉在功能稳定后完成。

## BUG-002：Esc、暂停与鼠标状态

**现状与证据**

[SettingsManager.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/Localization/SettingsManager.cs:120) 和 [FirstPersonController.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/Controllers/FirstPersonController.cs:253) 同时处理 Esc，分别切换设置和光标锁定。

[StartMenuBootstrap.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/SceneSystem/StartMenuBootstrap.cs:186) 在标题页打开设置时把 pauseGameWhenOpen、disablePlayerControlWhenOpen 改为 false。SettingsManager 跨场景保留，代码中没有对应的恢复。这是“从标题页设置进入游戏后，打开设置仍能移动”的明确候选原因。

关闭设置还会直接启用玩家、锁定光标，而不是恢复打开前的界面状态。已有 ModalCanvasLayerGuard 可以处理画布层级，但没有统一暂停与输入所有权。

**修改计划**

1. Esc 由一个界面控制入口处理，删除第一人称控制器里的独立 Esc 光标切换。
2. 建立可嵌套的界面状态：记录打开前的暂停、玩家控制和光标状态；关闭最上层界面后，恢复到仍存在的下层界面状态。
3. 标题设置、游戏设置使用明确上下文，不再永久修改共享布尔配置。
4. 设置打开时屏蔽移动、视角、道具使用和后台剧情推进；Time.timeScale=0 之外，还要处理 Update、点击推进和使用非缩放时间的逻辑。
5. 确保第一次打开前 UI 已初始化；明确 Esc 对背包、轮盘、显微镜等界面的优先级，避免一次按键被多个界面消费。
6. 检查 WebGL 原生指针锁释放与重新获取；桌面“继续游戏”的用户点击用于恢复指针锁，移动端保持触摸操作。

**验收**：一次 Esc 同时打开设置和光标；设置后游戏与相机不动；连续开关、标题设置→游戏设置、对话中打开设置、移动端菜单→设置都正常；点击设置不会触发采集。

**优先级/依赖**：最高，先于 BUG-008、009、011A 的界面接入。

## BUG-003：PC 道具图标过小

**现状与证据**

[InventoryUISystem.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/UISystem/InventoryUISystem.cs:378) 把内部 Icon 固定为 50×50；[UpdateSlotPositions](/Users/user/Unity/GeoModelTest/Assets/Scripts/UISystem/InventoryUISystem.cs:844) 只随轮盘调整槽位和文字，没有同步调整图标。截图中的“大方块、小图标”与此一致。

轮盘尺寸还直接把屏幕像素写入 RectTransform，需要按实际 Canvas 坐标核对缩放，不能仅继续增大整个轮盘。

**修改计划**

1. 图标按槽位内部区域缩放，初始取槽位的 65%～75%，保持宽高比，并检查素材透明边距。
2. 基于 Canvas 可用区域计算轮盘直径与上下限，给 PC、触摸设备设置不同的初始尺寸参数。
3. 统一图标、文字、选中背景和命中区域；名称最多两行，长名称正确换行。
4. 保留现有移动端点开、按下高亮、抬起确认逻辑，避免视觉修改改变选取行为。

**验收**：1366×768、1920×1080、窄嵌入窗口和 iPad 上图标清晰；高亮与实际选中道具一致；没有越界和文字遮挡。

**优先级/依赖**：中高，可与 BUG-004 使用同一套图标资源。

## BUG-005：对话溢出与日语注音

**现状与证据**

[StoryDirector.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/StorySystem/StoryDirector.cs:944) 的对话框占屏幕高度约 14%，正文固定 34 字号，再扣除上下边距，长句可用高度有限；当前没有显式分页流程。

[FuriganaProcessor.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/StorySystem/FuriganaProcessor.cs:144) 用 size、voffset、负 space 叠加注音，没有把基字与注音作为不可拆分的排版单元。截图中左侧越界与注音跨行相符，但具体换行位置仍需 TMP 渲染验证。

**修改计划**

1. 将说话人、正文、操作提示分为独立布局区域；对话框根据可用空间和文本测量结果扩展高度。
2. 修正注音布局：使用不可拆分的基字/读音单元，按实际排版宽度预留空间。先用 TMP 不换行分组做小型验证，若无法保证换行与分页正确，再采用独立 ruby 排版组件。
3. 实现长文分页，点击先翻页，最后一页才推进剧情；不能截断富文本标签或注音单元。
4. 题干、提示、错误/正确反馈复用同一个正文渲染入口；长选项也要按可用空间排布。
5. 保留可读字号下限；裁剪只作为边界保护，不能通过隐藏文字来掩盖溢出。

**验收**：用文档中的长反馈句、长注音、嵌套括号、三语长文本逐项测试；全部文字可读，翻页不跳剧情，不额外记录答题。

**优先级/依赖**：高，影响阅读和答题；其排版组件供 BUG-011A 复用。

## BUG-007：钻塔采样后返回研究室

**现状与证据**

[QuestManager.OnSampleAdded](/Users/user/Unity/GeoModelTest/Assets/Scripts/QuestSystem/QuestManager.cs:816) 在采样任务进行中收到样本后，直接播放 beat3 和 beat4，完成目标后又直接显示报告。该分支没有检查 sourceToolID，因此任意新增样本都可能触发钻塔阶段剧情。

**修改计划**

1. 明确有效岩芯采集条件：钻塔来源、成功入库、正确任务阶段，并按样本 ID 去重；排除仓库转移、读档恢复和普通采样事件。

4. 到达 Laboratory Scene 后才播放 beat3 的分析测验及 beat4 的比较/总结；检查台词中的地点描述，保持语言资源同步。
5. 为当前教学路径定义独立的完成条件，收尾后进入报告，避免激活旧章节 5、6。读取旧存档时按已有完成状态迁移，不重复采样或重复计分。
6. 为对话数据增加地点/通信方式与角色姿态字段；野外使用持手机版本，研究室使用普通版本。缺失素材时回退到已有角色图。需新增与现有角色一致的手机姿态素材。
7. 保留问题 ID；更新剧情路径/内容版本，保证修改前后的研究记录可区分。

**验收**：只有有效钻塔采样触发返程；野外不播放后续分析测验；返程提示后刷新仍可继续；研究室剧情只触发一次；最终报告在研究室出现。

**优先级/依赖**：高，属于流程修改；依赖稳定的界面输入与存档检查点。

## BUG-009：设置内返回标题与保存

**现状与证据**

SettingsManager 没有返回标题按钮；[MobileControlsUI.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/MobileSystem/MobileControlsUI.cs:2386) 已有“退出游戏”，WebGL 分支直接 LoadScene(StartScene)。这会绕过 GameSceneManager 的场景保存流程，并留下其缓存场景名未更新的风险。

[GameSceneManager.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/SceneSystem/GameSceneManager.cs:388) 已有切场景保存机制，但需要适配标题场景；不能把玩家恢复和强制锁鼠标等游戏场景逻辑直接套用到标题。

**修改计划**

4. 关闭/取消仍在运行的界面和剧情协程，释放暂停/输入状态，再通过场景服务进入标题；避免旧协程切场景后继续完成任务。

## BUG-010：新游戏确认框语言混用

## BUG-011B：参与者登录系统测试

**现状与证据**

[ResearchParticipationCoordinator.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/Backend/ResearchParticipationCoordinator.cs:45) 负责参与码入口；[TelemetryClient.cs](/Users/user/Unity/GeoModelTest/Assets/Scripts/Backend/TelemetryClient.cs:55) 先匿名认证，再请求 research-participation 验证参与码，成功后才启用研究会话。

已有 EditMode 测试覆盖研究开关、安装 ID、答题持久化、本地化和上传队列；[数据库测试](/Users/user/Unity/GeoModelTest/supabase/tests/research_foundation_v2_test.sql:6) 声明了 18 项断言，包括有效/无效/关闭/撤回参与资格及批次写入等。未发现完整的客户端登录→退出→重新登录端到端测试。

重点风险一：退出会清除本地认证，而服务端参与码仍绑定原匿名用户。下一次登录若创建新匿名身份，可能被判断为“参与码已绑定”。这需要用同一浏览器完整复现后确定恢复策略。

重点风险二：FinishResearchSession 在发送失败后仍会清空队列；断网退出可能丢失待上传研究记录，需要明确可恢复的退出行为并验证。

**测试与修改计划**

1. 先在独立开发数据上重跑已有 EditMode 与数据库测试，记录当前基线。
2. 补齐输入场景：有效码、无效码、大小写/空格、超长/非法字符、重复点击、请求超时、未登录及令牌过期。
3. 补齐身份场景：刷新后继续、正常退出后同一人再次进入、同一码不同浏览器、同设备更换参与者、参与资格撤回、研究入口关闭。
4. 区分正常结束会话、恢复同一参与者与清理设备身份；根据测试结果实现受控的身份恢复或重新绑定流程，避免只删除凭据却保留不可恢复绑定。
5. 补齐网络场景：离线暂存、重连补传、重复请求去重、服务端错误、限流，以及断网退出后的数据保留与重试。队列必须绑定参与者，切换身份后不能混传。
6. 核对数据库中的 participantId、sessionId、runId、问题 ID、内容版本与本地状态一致；普通游戏全过程不发起研究认证或上传。
7. 测试客户端只能通过现有 Edge Function 入口访问研究记录，普通身份不能直接读写研究表。错误提示统一成本地化文案，不向玩家显示内部异常。
8. 最后在实际 WebGL 嵌入页和 iPad 浏览器跑完整路径；本计划不把已有测试文件的存在视为测试通过。

**优先级/依赖**：若准备开展参与者测试，此项为高优先级。与 BUG-009 的退出语义和 BUG-008 的完成事件一起验证。
